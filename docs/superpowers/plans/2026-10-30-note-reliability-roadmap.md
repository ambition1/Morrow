# 笔记可靠性与版本记录实施方案

**Goal:** 按“记得快、找得到、不会丢”的顺序，完善家庭共享 Web 笔记的草稿恢复、冲突处理、版本记录、搜索及备份。

**Architecture:** 延用现有 WorkspaceSession、VaultRepository、Web VaultBridge、Markdown和附件结构。先补恢复基础，再接入冲突处理与版本界面；不新增账号系统，不把版本历史、离线草稿和整库备份混成一个功能。

**Tech Stack:** React、TypeScript、Tiptap、现有文件桥接与服务器版本检查、浏览器 IndexedDB、Docker Compose 部署脚本。

作者：xuanli；日期：2026-10-30。

## 当前事实与范围纠正

- 已有基础笔记历史：最多每十分钟生成一次自动快照、每篇最多50个，HistoryDialog已提供差异、预览和恢复；恢复前已有当前内容保护快照。应增强而非重建。
- 已有全文搜索、上下文片段、多处命中和打开后查找定位；本轮重点是筛选与精确命中定位，不能宣称这些基础能力尚不存在。
- 已有快速记录到今日笔记、模板、附件扫描、导出、历史附件引用保护和备份脚本。
- Web当前串行写入、库级revision拒绝陈旧写入、每五秒探测其他设备更新；目前仍以提示刷新为主。
- 用户已确认“版本记录”指笔记修改历史。本轮先实现第三阶段的笔记版本增强；其他阶段保留计划，不增加软件更新日志。

## 产品界面设计

### 保存状态

顶部只显示一种明确状态：正在保存／已保存／已存本机，等待同步／需要处理冲突／保存失败。点击状态可打开详情及恢复入口。断网时明确“已存本机”不等于“服务器已保存”。

### 恢复草稿

恢复网络或重新打开页面时，若存在未同步草稿，显示页面标题、最后编辑时间及恢复操作。服务器内容未变化可继续保存；已变化进入对比；无法判断时保留两份。清除草稿必须发生在服务器确认写入之后。

### 冲突处理

一个对比面板展示“本机草稿”和“服务器当前内容”，标明基准时间及差异。默认保留两份，不预选覆盖。首版提供保留为副本、采用服务器内容、手动合并后保存；自动合并只处理有明确共同基准且互不重叠的修改。冲突期间可以复制、导出本机内容。

### 笔记版本记录（已确认）

入口沿用页面选项中的历史记录，完善为“版本记录”。左侧时间线，右侧版本预览／与当前内容对比；显示明确时间及自动、手动、恢复前等来源。手动版本可命名，例如“会议确认稿”，重要版本可保留，避免自动清理。

- 自动版本沿用既有快照机制，避免每个按键都保存一版。
- 手动保存版本先等待当前内容保存成功；失败要保留输入并显示重试。
- 恢复是一次新的修改，先保护恢复前内容；若服务器已有更新，进入冲突处理，不能强制覆盖。
- 文本、提示块、日期、图册、引用和附件都可读；预览不允许编辑或跳转后丢失恢复上下文。
- 首版覆盖笔记正文；页面属性、数据库结构和整库恢复需要另行定义，不暗示已支持。
- 加密页面不能新增明文草稿或明文版本文件。未具备安全实现时明确不提供该能力。

## 分阶段实施与验收

### 第一阶段：P0草稿保护

涉及：src/app/platform/webVault.ts、src/app/workspace.ts、src/storage/session.ts、src/app/components/TopBar.tsx；新增独立草稿存储模块及测试。

- [ ] 明确草稿按服务器稳定身份、笔记库、页面ID隔离；多标签不互相覆盖草稿。
- [ ] IndexedDB保存文档、基准版本、更新时间和待上传附件；容量不足、隐私模式不可用均显示真实状态。
- [ ] 防抖保存及切页保护；应用启动读取草稿，不能用空初始状态覆盖已有草稿。
- [ ] 服务端写入确认后才标记已同步，乱序响应不能清除更新的草稿。
- [ ] 测试断网、刷新、误关、存储配额不足、恢复后再次失败和两个标签同时编辑。
- [ ] 首版支持已打开页面的草稿恢复；完整离线启动及PWA安装另列范围，不默认承诺。
